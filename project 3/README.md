# sample-size-mde-project

## Вычисление минимального детектируемого эффекта: симуляция Монте-Карло

### Источник
Karpov Courses, курс "Симулятор Аналитика", https://karpov.courses/simulator

Данные с 02.05.2026 до текущего дня (обновляются в режиме реального времени). В анализе использованы данные до 07.09.2026. Данные предоставлены в рамках курса, хранятся в Clickhouse.

### Структура данных
Провожу работу с данными стартапа приложения с лентой новостей (feed_actions) и мессенджером (message_actions). 

Таблица feed_actions- информация о действиях пользователей в приложении ленты новостей:
- user_id - идентификационный номер пользователя
- post_id - номер поста
- action - вид действия пользователя в ленте (категориальная переменная). Значения - like и view.
- time - дата и время действия пользователя в ленте новостей
- gender - пол пользователя
- age - возраст пользователя
- country - страна проживания пользователя
- city - город проживания пользователя
- os - операционная система устройства, с которого заходят в приложение
- source - канал привлечение клиентов: ads (через рекламу), organic (самостоятельно)
- exp_group - группа пользователя для проведения эксперимента

### Инструменты для работы
Python, выгрузка данных из Clickhouse
### Условие кейса
К нам пришли наши коллеги из ML-отдела и рассказали, что планируется выкатывать новый алгоритм, рекомендующий пользователям интересные посты. После обсуждений того, как он это делает, вы пришли к следующему пониманию:

- Алгоритм добавляет пользователям 1-2 просмотра
- Вероятность того, что он сработает, составляет 90%
- Если у пользователя меньше 50 просмотров, то алгоритм не сработает

Предполагается, что увеличение числа просмотров приведёт и к увеличению лайков на пользователя.

Вопрос: сможем ли мы обнаружить различия в среднем количестве лайков на пользователя?

### Цель задания
- Симуляция A/B-эксперимента для оценки необходимых параметров его проведения
- Выявить, какой процент статистически значимых различий среднем количестве лайков на пользователя сможет выявить тест при имеющемся наборе параметров, иными словами, мощность теста.
- Определить зависимость мощности теста от выбранных параметров

### Инструменты анализа
Симуляция A/B эксперимента методом Монте-Карло, статистический t-test для сравнения средних значений

### Симуляция Монте-Карло
Дизайн эксперимента:

- Семплирую просмотры для обеих групп из реальных данных: group_A_views и group_B_views
- Беру группу B за экспериментальную (на нее распространяется изменение)
- Рассчитываю ожидаемый эффект на просмотры (group_B)
- Семплирую ctr для обеих групп: group_A_CTR и group_B_CTR
- Создаю биномиальное распределение для просмотров пользователей группы А и просмотров пользователей группы B с эффектом. CTR берется для оценки вероятности клика.
- Провожу t-тест с учетом неравенства дисперсий

**1. Исходные параметры**

- Симулируем просмотры и CTR из реальных данных. Реальные данные принимаются за генеральную совокупность, а выборки семлирую.
- Даты проведения эксперимента: 22.05.2026 - 28.05.2026 (1 неделя)
- Количество симуляций задайте не меньше 20000
- Эффект алгоритма на просмотры: group_B_views + ((1 + rng.binomial(n=1, p=0.5, size=размер_выборки)) * rng.binomial(n=1, p=0.9, size=размер_выборки) * (group_B_views >= 50))
- Лайки сравниваем t-тестом с поправкой Уэлча на неравные дисперсии
- Уровень значимости - 0.05
- Делим пользователей на группы 50/50

-> Получила мощность теста - **0.2534**

**2. Изменение алгоритма 1**

Алгоритм улучшен: рекомендации отправляются всем пользователям с просмотрами больше 30.

-> Получила мощность теста - **0.4178**

**3. Изменение алгоритма 2**

Эксперимент продлен до 2-х недель. Рост размера выборок в обеих группах.

-> Получила мощность теста - **0.5624**

**4. Изменение алгоритма 3**

Теперь фильтрую только по нужных пользователям (тем, чьи просмотры выше 30) и отправляю только их в t-тест. При этом снижается размер выборок.

-> Получила мощность теста - **0.6484**

### Вывод
- C ростом продолжительности эксперимента, размера выборки, чувствительности теста растет процент случаев, когда он может зафиксировать статистически значимые различия между средними значениями по группам.
- Параметры компенсируют друг друг: повышение чувствительности теста требует меньшего размера выборки.

**Мощность теста после улучшений остается низкой по сравнению со стандартом в 80%**. Вероятно, для повышения мощности необходимо увеличить количество симуляций или поработать над новым алгоритмом так, чтобы он охватывал пользователей и с меньшим количеством просмотров.
